# v0.1.0 验收清单

供真机人工验收逐项勾选。对应 [rewrite-plan.md](rewrite-plan.md) 第 8 节。

**准备：**
- 服务端：部署到自己的 Cloudflare 账号（见 [server/README.md](../server/README.md)），或在本机运行 `mise run dev-server`（验证码打印在终端里）。
- 手机：从 Releases 安装 APK。连接本机开发服务端时，Android 模拟器使用 `http://10.0.2.2:8787`；真机请使用部署后的 HTTPS 地址。
- 电脑：一台 Mac、一台 Linux（VPS 或虚拟机），用 `install.sh` 安装 CLI。

开发自检（不等于验收）已覆盖：三端单元测试、服务端 13 项、`e2e/run.sh` 覆盖 J1、J3–J9 的非界面部分、模拟器布局检查。

## B. 核心流程

- [ ] **J1 首次设置**：连接服务器 → 注册 →（开启邮箱验证时）输入邮件验证码 → 设置 App PIN（手机支持指纹时直接弹出指纹验证，通过即开启指纹解锁；取消后可以重试或点“跳过”）→ 保存恢复码（抄写，或“复制”，提示 1 分钟后清空剪贴板）并完整重输 → 完成页提示恢复码已生效，必须“下载 PDF”并保存后才能点“完成”（打印正常）→ 进入“环境”页
- [ ] **J2 日常使用**：冷启动先要求解锁（开启了指纹时先弹指纹，可以改输 PIN；没开启时输入 PIN）；退到后台超过 5 分钟再回来需要重新解锁；设置中没有关闭 App 锁的选项
- [ ] **J3 电脑接入**：`harmonia login <地址>` → 手机“设备 → 添加设备”扫码 → 选择环境与权限 → 批准 → 终端显示“已接入账号”
- [ ] **J3 核对码**：在“添加设备”中选择“输入核对码”，手输终端显示的 16 位码也能完成配对
- [ ] **J4 使用变量**：授权的环境默认已激活，安装 shell 集成后新开终端 `echo $变量名` 有值；`harmonia exec -- printenv 变量名` 有值
- [ ] **J4 激活与顺序**：在手机“设备详情”中关闭某个环境或拖动调整顺序，电脑几秒内 `env.sh` 随之变化；在电脑上 `harmonia env deactivate`、`harmonia env order` 后，手机上看到同样的状态；两个环境有同名变量时，手机和 `harmonia env list` 都显示由哪个环境提供
- [ ] **J4 实时同步**：安装后台服务并加载 shell 集成后，在手机上新增、修改、删除变量；同步完成后，原终端按一次空回车，新增和修改生效，删除的变量恢复原值或移除，无需重开终端（Linux Bash、macOS Zsh 各验证一次）
- [ ] **J5 电脑写入**：读写权限的电脑 `harmonia var set <环境> <名> <值>` 后，手机上能看到；`harmonia import --env <环境>` 只上传勾选的变量
- [ ] **J6 本地覆盖与退出**：`harmonia override set` 只影响本机；云端删除该变量后覆盖失效；`harmonia logout` 后原终端在下次提示符出现时恢复接管前的变量状态，原来不存在的变量被移除
- [ ] **J7 降权**：手机上把电脑改为“只读”，电脑 `harmonia var set` 提示只读
- [ ] **J7 撤销**：手机上移除电脑，在线电脑几秒内清除本机数据（`harmonia status` 显示未接入，`env.sh` 变空）；离线电脑联网后清除
- [ ] **J7 到期**：授权设置“1 天”，到期后电脑停用该环境（可把手机时间往后调验证服务端拒绝；电脑离线同样停用）
- [ ] **J8 恢复**：卸载 App 或换一台手机 → 登录 → 设置 App PIN → “用恢复码恢复” → 强制更换恢复码（可同时设置新密码）→ 进入主页；旧恢复码再用会提示不对
- [ ] **J8 检查其他设备**：恢复完成（保存 PDF 后点“完成”）进入“检查其他设备”页，列出旧手机和已接入的电脑，默认都不勾选；勾选多台后点“移除所选”，确认并只验证一次身份即可全部移除，被移除的设备联网后清除本机数据；不勾选时点“完成”进入主页。账号中没有其他设备时不显示这一页；设置中主动更换恢复码不显示这一页
- [ ] **J9 第二台管理设备**：第二台手机登录 → 设置 App PIN → “让管理设备批准” → 第一台扫码、开启“作为管理设备”批准 → 第二台能看到并管理全部环境；之后可以移除它
- [ ] **J10 更新**：发布两个版本后，App“检查更新”能下载并安装新版本、数据保留；`harmonia update` 能升级并重启后台服务
- [ ] **J10 更新渠道**：App“设置 → 更新渠道”切到测试版后能收到 `-rc`/`-beta` 版本，正式版渠道收不到；`harmonia update channel beta` 同理；`v0.1.2` 发布后测试版用户也会升到它

## C. 生命周期

- [ ] 服务端 Sync fork 更新后，App 和 CLI 继续可用
- [ ] App 覆盖安装升级数据保留；卸载重装视为新设备
- [ ] `harmonia uninstall` 移除后台服务、rc 文件中的那几行、`~/.harmonia` 和程序本身
- [ ] 删除环境后，所有电脑同步移除其中的变量
- [ ] 重启电脑后后台服务自动运行（Linux 无需登录；macOS 登录后）
- [ ] 设置中修改登录密码、更换恢复码、修改 App PIN、开关指纹解锁
- [ ] **颜色模式**：设置中可切换亮色、暗色和跟随系统；默认跟随系统，切换立即生效并在重启、退出账号后保留；与液态玻璃开关独立，调试区切换不影响真实设置。
- [ ] **液态玻璃外观（Android 与 iOS）**：首次安装默认关闭；“设置 → 外观 → 液态玻璃”开启后，底部切换为贴近屏幕底部的悬浮胶囊导航，顶部切换为大标题或居中标题与独立操作按钮，环境菜单、对话框和更新弹层采用悬浮布局，关闭后恢复原样；更新弹层长正文可滚动、操作区固定；列表与输入框保持清晰实色，按钮、返回和取消行为不变。重启与退出账号后保留本机选择，另一台设备不受影响；深浅色、高对比度、减少动态效果下可读且可操作，滚动与返回动画流畅
- [ ] **页面调试**：从设置最底部进入，全部页面、弹窗和分步状态可访问；两种外观、明暗主题、大字号、离线、空数据与失败场景可切换。模拟增删改查跨页一致，退出重进恢复样例；任何地址、账号或操作都不读取真实数据、不发网络请求、不调用真实生物识别/相机/文件导出/安装，且随时可以返回目录或退出调试。

## D. 异常场景（每项都应有明确提示）

- [ ] 地址错误 / 不是 Harmonia 服务 / 服务器连不上
- [ ] 密码错误；连续失败后提示稍后再试
- [ ] 配对超过 10 分钟过期；扫了别的二维码；在手机上拒绝配对
- [ ] 管理设备在前台时运行 `harmonia login`，手机直接弹出批准页；App 在后台时发起，打开 App 后弹出
- [ ] 终端等待批准时按 Ctrl+C（或新手机离开等待页）：手机不再弹出；已经打开的批准页显示请求已失效
- [ ] 拒绝时勾选阻止这个网络：同一网络 30 分钟内再发起配对，提示暂时不能发起
- [ ] 在管理设备上修改密码后，之前未处理的配对请求作废，发起方提示重新登录
- [ ] 一个网络连续输错密码：提示等待时间且逐渐变长；同时在另一个网络正常登录不受影响
- [ ] 账号受攻击时（多个网络大量失败），配置了发信的服务器登录要求输入邮件验证码；未配置发信时输对密码可以登录，输错后提示等待
- [ ] 别人反复输错找回密码验证码，不影响自己收到的验证码；验证码发送过多时提示稍后再试，已收到的验证码仍可用
- [ ] 写入变量、批准设备、更换恢复码时断网
- [ ] 电脑离线时 `harmonia exec` 使用缓存并提示
- [ ] 两台设备同时修改同一变量，最终一致
- [ ] 删除一个电脑正在使用的环境
- [ ] 已撤销的电脑再次联网
- [ ] App 被系统杀掉后重新打开
- [ ] 恢复码输错
- [ ] App PIN 连续输错：5 次后要求等待，等待时间递增；杀掉 App 重开后仍需等待
- [ ] 新增或删除手机指纹、或关闭手机锁屏后打开 App：改用 PIN 解锁，提示指纹解锁已关闭，可以在设置中重新开启，数据都在
- [ ] 忘记 PIN（未开启指纹）：锁屏页“忘记 PIN”清除本机数据，重新登录后可由管理设备批准或用恢复码恢复；旧设备记录可在其他设备上移除
- [ ] rc 文件是符号链接（例如由 dotfiles 工具管理）时 `harmonia shell install` 给出手动添加说明
- [ ] 用 `install.sh` 安装时询问是否安装 shell 集成和后台服务，直接回车两项都装好；输入 n 则跳过，`harmonia login` 完成后提示对应命令；重复运行时 shell 集成提示已安装
- [ ] 忘记密码：登录页“忘记密码”通过邮件验证码重设（需配置发信；未配置时提示服务器没有配置发信）
- [ ] 重置账号：登录页“重置账号”删除数据后可用同一邮箱重新注册（需配置发信）

## F. 新用户测试

在全新的 Cloudflare 账号、没装过 App 的手机、干净的 Linux 和 Mac 上，只看 README 完成：部署 → 使用 → 撤销 → 恢复 → 升级 → 卸载。任何卡住的地方都记为缺陷。

# v0.2.0：iOS App

对应 [rewrite-plan.md](rewrite-plan.md) 第 14 节。以下各项在 iPhone 真机上验收；没有列出的流程与 Android 相同，不重复验收。

**准备：** 从 Releases 下载 `harmonia-<版本>.ipa`，用 AltStore、SideStore 或自己的开发者证书签名安装；另备一台已接入账号的 Android 手机和一台电脑。

## 核心流程

- [ ] **安装**：只看 README 能把 IPA 签名并安装到 iPhone 上，App 能打开
- [ ] **J1 首次设置**：连接服务器 → 注册 → 设置 App PIN → 直接弹出面容 ID（或触控 ID）验证，通过即开启；取消后可以重试或点“跳过” → 保存恢复码（复制后提示 1 分钟后清空，1 分钟后粘贴不出内容）并完整重输 → 完成页“下载 PDF”弹出“存储到文件”，保存后才能点“完成”；PDF 为一页 A4，打印正常
- [ ] **J2 日常使用**：冷启动先弹面容 ID，验证期间屏幕上显示的是锁定页而不是空白，取消后可以改输 PIN；退到后台超过 5 分钟再回来需要重新解锁
- [ ] **J3 批准电脑**：电脑 `harmonia login`，iPhone 在前台时直接弹出批准页；“设备 → 添加设备”扫码（首次询问相机权限）和手输核对码都能完成配对
- [ ] **J4 管理**：在 iPhone 上新增、修改、删除变量，开关环境、拖动排序，电脑几秒内同步
- [ ] **J8 恢复**：在 iPhone 上用恢复码恢复 → 强制更换恢复码 → 检查其他设备
- [ ] **J9 两个平台互相批准**：Android 手机批准 iPhone 成为管理设备，反过来也可以；设备列表中 iPhone 显示为“iPhone”，可以互相移除
- [ ] **J10 更新**：发布更高的版本后，“检查更新”显示新版本和更新说明；点“下载并导入签名工具”，下载完成后弹出系统分享面板，面板里能看到安装时使用的签名工具（轻松签、全能签、万能签等），选中后新的 IPA 出现在签名工具里，签名安装后数据保留；在面板里取消不报错；“打开下载页”可用；更新渠道切换与 Android 表现一致

## 生命周期与异常

- [ ] 卸载后重新安装：需要重新登录并设置 App PIN，旧的 PIN 和面容 ID 解锁不残留；旧设备记录可以在其他设备上移除
- [ ] 签名过期（免费 Apple ID 为 7 天）后重新签名，App 能打开，数据保留
- [ ] 新增或删除面容、指纹，或关闭手机锁屏密码后打开 App：改用 PIN 解锁，提示面容 ID（触控 ID）解锁已关闭，可以在设置中重新开启，数据都在
- [ ] 手机没有设置面容 ID 或触控 ID：设置 PIN 后不询问，设置中不显示这一项
- [ ] 在系统设置中关闭 Harmonia 的面容 ID 权限：改用 PIN 解锁，不卡住
- [ ] App PIN 连续输错 5 次后要求等待，杀掉 App 重开后仍需等待；“忘记 PIN”清除本机数据后可以重新接入
- [ ] 拒绝相机权限：扫码页提示可以改为输入核对码，或到系统设置中允许
- [ ] 被其他管理设备移除后，iPhone 联网即清除本机数据并回到登录页
- [ ] 签名校验失败或网络不通时，“检查更新”给出明确提示，不显示“已是最新版本”
- [ ] “设置 → 关于 Harmonia”显示版本和开源项目列表，点开任意一项能看到版权说明和许可证全文（Android 同样验收一次）

# v0.3.0：Windows CLI

对应 [rewrite-plan.md](rewrite-plan.md) 第 15 节。以下各项在 Windows 真机上验收；没有列出的命令（环境、变量、本地覆盖、导出）与 macOS、Linux 相同，不重复验收。

**准备：** 一台 Windows 10 或 11 的电脑（普通权限的 PowerShell 窗口即可），一台已接入账号的手机。

## 核心流程

- [ ] **安装**：只看 README，用一行命令装好；全程没有要求管理员权限，也没有要求修改脚本执行策略；新开一个终端后 `harmonia version` 可用
- [ ] **J3 接入**：`harmonia login <服务器地址>`，终端里的二维码能被手机扫到，核对码也能手输；批准后终端显示接入成功，手机的设备列表里这台电脑显示为“Windows”
- [ ] **J4 变量生效**：开启“写入用户环境变量”后，新开的 PowerShell、cmd 和从开始菜单启动的程序都能读到变量；“系统属性 → 环境变量”的用户变量里能看到它们
- [ ] **J4 实时同步**：在手机上修改一个值，几秒后新开的终端里是新值；已经打开的终端不变，`harmonia exec -- <命令>` 在旧终端里也能拿到新值
- [ ] **J4 exec**：`harmonia exec -- cmd /c echo %变量名%` 输出正确；被运行的程序以非零退出码结束时，`harmonia exec` 的退出码相同；Ctrl+C 能结束被运行的程序
- [ ] **后台服务**：安装后立即运行，`harmonia service status` 显示运行中；重启电脑并登录后自动运行，登录时没有窗口弹出或闪过
- [ ] **J10 更新**：发布更高的版本后，`harmonia update` 完成升级并重启后台服务，`harmonia version` 显示新版本；更新渠道切换与其他平台一致

## 生命周期与异常

- [ ] **原有变量不丢**：先手动建一个用户变量，再让 Harmonia 写入同名变量，新终端里是 Harmonia 的值；在手机上删掉这个变量（或停用环境）后，新终端里恢复成自己原来的值
- [ ] **系统变量默认不写入**：环境里有名为 `PATH` 或 `TEMP` 的变量时，用户变量里的 `Path`、`TEMP` 保持原样，`harmonia status` 说明它们没有写入以及怎么开启
- [ ] **系统变量开关**：在手机的设备详情页打开这台电脑的“写入系统变量”，几秒后用户变量里的 `TEMP` 变成 Harmonia 的值；关闭后恢复原值。`harmonia shell system-vars on|off` 效果相同，手机上的开关随之变化；Mac、Linux 设备的详情页没有这个开关
- [ ] **撤销**：在手机上移除这台电脑后，后台服务几秒内把写入的用户变量全部恢复，`harmonia status` 显示没有接入账号
- [ ] **到期**：授权到期后，一分钟左右对应的用户变量被恢复
- [ ] **退出登录**：`harmonia logout` 后写入的用户变量全部恢复，开关保持开启；重新接入后自动写回
- [ ] **关闭开关**：`harmonia shell uninstall` 后写入的用户变量全部恢复，之后同步不再写入
- [ ] **卸载**：`harmonia uninstall` 后，用户变量恢复、计划任务消失、数据目录和程序被删除、用户 `Path` 里没有安装目录；重新安装可以正常使用
- [ ] 值里含有 `%`、引号、空格、中文、换行时，新终端里读到的内容与手机上一致
- [ ] 断网时命令给出明确提示；恢复联网后后台服务自动重连并同步
- [ ] 在同一台电脑的 WSL 里安装 Linux 版，两边互不影响（各自是一台设备）

# v0.3.1：服务器首页与扫码连接

对应 [rewrite-plan.md](rewrite-plan.md) 5.5 的“实例首页”。

- [ ] 在电脑浏览器里打开服务器地址，看到首页：显示“运行中”、这台服务器的地址和二维码、三步开始使用；深色模式下也清楚
- [ ] 在手机浏览器里打开服务器地址，页面没有横向滚动，命令能完整看到
- [ ] 首页上的三条命令可以整行选中复制，登录命令里的地址就是这台服务器的地址
- [ ] **扫码连接**：全新安装的 App 在“连接服务器”页点“扫码填写”，扫电脑上首页的二维码，直接进入登录 / 注册页，显示的服务器地址正确
- [ ] 扫到别的二维码（例如电脑终端里的配对二维码）时提示这不是服务器的二维码，可以继续扫；拒绝相机权限时提示改为手动填写
- [ ] 用手机相机（不是 App）扫首页的二维码，会在浏览器里打开这张首页
- [ ] 在浏览器里打开 `<服务器地址>/api/v1/instance`，其中的 `version` 与部署的版本一致
