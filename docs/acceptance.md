# v0.1.0 验收清单

供真机人工验收逐项勾选。对应 [rewrite-plan.md](rewrite-plan.md) 第 8 节。

**准备：**
- 服务端：部署到自己的 Cloudflare 账号（见 [server/README.md](../server/README.md)），或在本机运行 `mise run dev-server`（验证码打印在终端里）。
- 手机：从 Releases 安装 APK。连接本机开发服务端时，Android 模拟器使用 `http://10.0.2.2:8787`；真机请使用部署后的 HTTPS 地址。
- 电脑：一台 Mac、一台 Linux（VPS 或虚拟机），用 `install.sh` 安装 CLI。

开发自检（不等于验收）已覆盖：三端单元测试、服务端 13 项、`e2e/run.sh` 覆盖 J1、J3–J9 的非界面部分、模拟器布局检查。

## B. 核心流程

- [ ] **J1 首次设置**：连接服务器 → 输入邮箱（没有密码输入框），提示还没有注册，确认创建新账号 →（开启邮箱验证时）输入邮件验证码 → 设置 App PIN（手机支持指纹时直接弹出指纹验证，通过即开启指纹解锁；取消后可以重试或点“跳过”）→ 保存恢复码（抄写，或“复制”，提示 1 分钟后清空剪贴板）并完整重输 → 完成页提示恢复码已生效，必须“下载 PDF”并保存后才能点“完成”（打印正常）→ 进入“环境”页
- [ ] **J2 日常使用**：冷启动先要求解锁（开启了指纹时先弹指纹，可以改输 PIN；没开启时输入 PIN）；退到后台超过 5 分钟再回来需要重新解锁；设置中没有关闭 App 锁的选项
- [ ] **J3 电脑接入（扫码）**：`harmonia login <地址>` 依次询问邮箱和配对码，不询问密码；配对码直接回车留空 → 终端显示二维码、核对码和“5 分钟内有效” → 手机不弹出批准页，“设备”页没有待批准项、底栏没有角标 → 手机“设备 → 添加设备”，在展开的菜单中选择“扫码确认” → 扫码 → 选择环境与权限 → 批准 → 终端显示“已接入账号”
- [ ] **J3 核对码**：同样不带配对码发起，在扫码页中选择“输入核对码”，手输终端显示的 16 位码也能找到这次请求并完成配对
- [ ] **J3 配对码**：手机“设备 → 添加设备”，从按钮展开浮动菜单（“生成配对码”“扫码确认”两项；普通外观是底部按钮，液态玻璃外观是标题栏的加号），选择“生成配对码”，不经过扫码页，弹窗先显示有效期（默认 10 分钟，可选 5 到 60 分钟），点“生成”后显示 8 位配对码和剩余时间（从所选时间倒数）→ 电脑 `harmonia login <地址>` 时输入这个配对码（或用 `--code`）→ 手机在前台时直接弹出批准页，“设备”页的待批准列表和角标出现这台电脑 → 批准页仍要求勾选“核对码一致”才能批准 → 批准后终端显示“已接入账号”
- [ ] **J3 配对码只能用一次**：用过的配对码再用一次，终端提示配对码不对或已过期、可以重新生成或留空改用扫码；连续生成两个配对码，两个都能用；超过所选有效期再用，同样提示过期
- [ ] **J4 使用变量**：授权的环境默认已激活，安装 shell 集成后新开终端 `echo $变量名` 有值；`harmonia exec -- printenv 变量名` 有值
- [ ] **J4 激活与顺序**：在手机“设备详情”中关闭某个环境或拖动调整顺序，电脑几秒内 `env.sh` 随之变化；在电脑上 `harmonia env deactivate`、`harmonia env order` 后，手机上看到同样的状态；两个环境有同名变量时，手机和 `harmonia env list` 都显示由哪个环境提供
- [ ] **J4 实时同步**：安装后台服务并加载 shell 集成后，在手机上新增、修改、删除变量；同步完成后，原终端按一次空回车，新增和修改生效，删除的变量恢复原值或移除，无需重开终端（Linux Bash、macOS Zsh 各验证一次）
- [ ] **J5 电脑写入**：读写权限的电脑 `harmonia var set <环境> <名> <值>` 后，手机上能看到；`harmonia import --env <环境>` 只上传勾选的变量
- [ ] **J6 本地覆盖与退出**：`harmonia override set` 只影响本机；云端删除该变量后覆盖失效；`harmonia logout` 后原终端在下次提示符出现时恢复接管前的变量状态，原来不存在的变量被移除
- [ ] **J7 降权**：手机上把电脑改为“只读”，电脑 `harmonia var set` 提示只读
- [ ] **J7 撤销**：手机上移除电脑，在线电脑几秒内清除本机数据（`harmonia status` 显示未接入，`env.sh` 变空）；离线电脑联网后清除
- [ ] **J7 到期**：授权设置“1 天”，到期后电脑停用该环境（可把手机时间往后调验证服务端拒绝；电脑离线同样停用）
- [ ] **J8 恢复**：卸载 App 或换一台手机 → 输入邮箱 → 设置 App PIN → “用恢复码恢复” → 强制更换恢复码（页面上没有“设置新密码”）→ 进入主页；旧恢复码再用会提示不对
- [ ] **J8 检查其他设备**：恢复完成（保存 PDF 后点“完成”）进入“检查其他设备”页，列出旧手机和已接入的电脑，默认都不勾选；勾选多台后点“移除所选”，确认并只验证一次身份即可全部移除，被移除的设备联网后清除本机数据；不勾选时点“完成”进入主页。账号中没有其他设备时不显示这一页；设置中主动更换恢复码不显示这一页
- [ ] **J9 第二台管理设备**：第二台手机输入邮箱 → 设置 App PIN → “接入这台手机”，配对码留空 → 显示二维码和核对码 → 第一台扫码、开启“作为管理设备”批准 → 第二台能看到并管理全部环境；之后可以移除它
- [ ] **J9 用配对码接入手机**：第一台生成配对码 → 第二台“接入这台手机”时输入配对码 → 第一台在前台直接弹出批准页，核对核对码后批准 → 第二台成为管理设备
- [ ] **J10 更新**：发布两个版本后，Android App“检查更新”同时显示“下载并安装”和“打开下载页”；前者能下载并安装新版本、数据保留，后者打开对应版本的发布页，未授予安装权限时也能使用且不会触发下载；无法打开时给出可操作的提示；页面调试使用相同按钮文案，下载与打开下载页均只模拟；`harmonia update` 能升级并重启后台服务
- [ ] **J10 在手机上让电脑更新**：电脑装着旧版本和后台服务，发布更高的版本后，手机“设备详情 → 版本与更新”显示当前版本和新版本；点“更新”，电脑上不弹任何确认，1 分钟内完成升级，手机上的版本几秒内变成新版本，`harmonia version` 一致，后台服务继续运行、变量照常同步；电脑关机或停掉后台服务时点“更新”，App 提示后台服务没有连上服务器和下一步怎么做
- [ ] **J10 自动更新**：在手机上打开某台电脑的“自动更新”，电脑 `harmonia update auto` 显示已开启；在电脑上 `harmonia update auto off`，手机上几秒内显示关闭；开启后发布新版本，电脑在下一次每天的检查（或刚开启时的那次检查）中自动升级；关闭时只提示不升级
- [ ] **J10 更新提示**：有新版本且自动更新关闭时，在终端里运行 `harmonia env list`，输出后面出现一次更新提示，当天再运行不再出现；`harmonia env list 2>&1 | cat` 和 AI 助手调用时不出现；`harmonia status` 每次都显示
- [ ] **J10 更新渠道**：App“设置 → 更新渠道”切到测试版后能收到 `-rc`/`-beta` 版本，正式版渠道收不到；`harmonia update channel beta` 同理；`v0.1.2` 发布后测试版用户也会升到它

## C. 生命周期

- [ ] 服务端 Sync fork 更新后，App 和 CLI 继续可用
- [ ] App 覆盖安装升级数据保留；卸载重装视为新设备
- [ ] `harmonia uninstall` 移除后台服务、rc 文件中的那几行、`~/.harmonia` 和程序本身
- [ ] 删除环境后，所有电脑同步移除其中的变量
- [ ] 重启电脑后后台服务自动运行（Linux 无需登录；macOS 登录后）
- [ ] 设置中更换恢复码、修改 App PIN、开关指纹解锁；设置中没有“修改登录密码”，输入邮箱页没有“忘记密码”
- [ ] **颜色模式**：设置中可切换亮色、暗色和跟随系统；默认跟随系统，切换立即生效并在重启、退出账号后保留；与液态玻璃开关独立，调试区切换不影响真实设置。
- [ ] **液态玻璃外观（Android 与 iOS）**：未保存过外观设置时，iOS 26 及以上默认开启，Android 与较早 iOS 默认关闭，已保存的选择优先；“设置 → 外观 → 液态玻璃”开启后，底部切换为贴近屏幕底部的悬浮胶囊导航，顶部切换为大标题或居中标题与独立操作按钮，环境菜单、对话框和更新弹层采用悬浮布局，关闭后恢复原样；更新弹层常规高度下长正文可滚动、操作区固定，短屏和大字号下整层可滚动；首页弹窗打开键盘只避让一次，普通 PIN 弹窗使用标准滚动布局；列表与输入框保持清晰实色，按钮、返回和取消行为不变。重启与退出账号后保留本机选择，另一台设备不受影响；深浅色、高对比度、减少动态效果下可读且可操作，滚动与返回动画流畅
- [ ] **页面调试**：默认看不到入口；在“关于”页连点 5 次版本号后从设置最底部进入，“关闭开发者选项”后入口消失，全部页面、弹窗和分步状态可访问；两种外观、明暗主题、大字号、离线、空数据与失败场景可切换。模拟增删改查跨页一致，退出重进恢复样例；任何地址、账号或操作都不读取真实数据、不发网络请求、不调用真实生物识别/相机/文件导出/安装，且随时可以返回目录或退出调试。

## D. 异常场景（每项都应有明确提示）

- [ ] 地址错误 / 不是 Harmonia 服务 / 服务器连不上
- [ ] 输入没有注册过的邮箱：提示还没有注册，确认后才创建新账号；服务器没有开放注册时提示不能注册；`harmonia login` 提示先在 App 中注册
- [ ] 输入已注册但还没完成设置的邮箱（例如注册后没保存恢复码就卸载了 App）：提示重新开始设置，确认后重新注册并初始化
- [ ] 配对码输错：提示配对码不对或已过期，可以在管理设备上重新生成或留空改用扫码；同一网络连续输错 5 次后提示等待时间且逐渐变长；另一个网络用正确的配对码不受影响
- [ ] 配对超过 5 分钟过期；扫了别的二维码；在手机上拒绝配对
- [ ] 管理设备在前台时用配对码运行 `harmonia login`，手机直接弹出批准页；App 在后台时发起，打开 App 后弹出。不带配对码发起时都不弹出
- [ ] 匿名请求额度占满（别人用你的邮箱从多个网络发起了 20 个不带配对码的请求并一直等待）：`harmonia login` 不带配对码时提示额度已满、请在管理设备上生成配对码；带配对码可以正常接入。每个网络最多同时 2 个，需要从 10 个以上的网络同时发起，真机上难以构造，额度计数由服务端单元测试覆盖，这里只在有条件时验收提示文案
- [ ] 终端等待批准时按 Ctrl+C（或新手机离开等待页）：手机不再弹出；已经打开的批准页显示请求已失效
- [ ] 拒绝时勾选阻止这个网络：同一网络 30 分钟内再发起配对，提示暂时不能发起
- [ ] 批准页（自动弹出或从列表打开）提示只批准自己刚刚发起的请求，并显示设备名、平台和来源 IP
- [ ] 别人反复输错重置账号验证码，不影响自己收到的验证码；验证码发送过多时提示稍后再试，已收到的验证码仍可用
- [ ] 写入变量、批准设备、更换恢复码时断网
- [ ] 电脑离线时 `harmonia exec` 使用缓存并提示
- [ ] 两台设备同时修改同一变量，最终一致
- [ ] 删除一个电脑正在使用的环境
- [ ] 已撤销的电脑再次联网
- [ ] App 被系统杀掉后重新打开
- [ ] 恢复码输错
- [ ] App PIN 连续输错：5 次后要求等待，等待时间递增；杀掉 App 重开后仍需等待
- [ ] 新增或删除手机指纹、或关闭手机锁屏后打开 App：改用 PIN 解锁，提示指纹解锁已关闭，可以在设置中重新开启，数据都在
- [ ] 忘记 PIN（未开启指纹）：锁屏页“忘记 PIN”清除本机数据，重新输入邮箱后可由管理设备批准或用恢复码恢复；旧设备记录可在其他设备上移除
- [ ] rc 文件是符号链接（例如由 dotfiles 工具管理）时 `harmonia shell install` 给出手动添加说明
- [ ] 用 `install.sh` 安装时询问是否安装 shell 集成和后台服务，直接回车两项都装好；输入 n 则跳过，`harmonia login` 完成后提示对应命令；重复运行时 shell 集成提示已安装
- [ ] 重置账号：输入邮箱页的“重置账号”删除数据后可用同一邮箱重新注册（需配置发信）

## F. 新用户测试

在全新的 Cloudflare 账号、没装过 App 的手机、干净的 Linux 和 Mac 上，只看 README 完成：部署 → 使用 → 撤销 → 恢复 → 升级 → 卸载。任何卡住的地方都记为缺陷。

# v0.2.0：iOS App

对应 [rewrite-plan.md](rewrite-plan.md) 第 14 节。以下各项在 iPhone 真机上验收；没有列出的流程与 Android 相同，不重复验收。

**准备：** 从 Releases 下载 `harmonia-<版本>.ipa`，用 AltStore、SideStore 或自己的开发者证书签名安装；另备一台已接入账号的 Android 手机和一台电脑。

## 核心流程

- [ ] **安装**：只看 README 能把 IPA 签名并安装到 iPhone 上，App 能打开
- [ ] **J1 首次设置**：连接服务器 → 注册 → 设置 App PIN → 直接弹出面容 ID（或触控 ID）验证，通过即开启；取消后可以重试或点“跳过” → 保存恢复码（复制后提示 1 分钟后清空，1 分钟后粘贴不出内容）并完整重输 → 完成页“下载 PDF”弹出“存储到文件”，保存后才能点“完成”；PDF 为一页 A4，打印正常
- [ ] **J2 日常使用**：冷启动先弹面容 ID，验证期间屏幕上显示的是锁定页而不是空白，取消后可以改输 PIN；退到后台超过 5 分钟再回来需要重新解锁
- [ ] **J3 批准电脑**：iPhone 生成配对码，电脑用它 `harmonia login`，iPhone 在前台时直接弹出批准页；不带配对码时不弹出，“设备 → 添加设备”扫码（首次询问相机权限）和手输核对码都能完成配对
- [ ] **J4 管理**：在 iPhone 上新增、修改、删除变量，开关环境、拖动排序，电脑几秒内同步
- [ ] **J8 恢复**：在 iPhone 上用恢复码恢复 → 强制更换恢复码 → 检查其他设备
- [ ] **J9 两个平台互相批准**：Android 手机批准 iPhone 成为管理设备，反过来也可以；设备列表中 iPhone 显示为“iPhone”，可以互相移除
- [ ] **J10 更新**：发布更高的版本后，“检查更新”显示新版本和更新说明；点“下载并导入签名工具”，下载完成后弹出系统分享面板，面板里能看到安装时使用的签名工具（轻松签、全能签、万能签等），选中后新的 IPA 出现在签名工具里，签名安装后数据保留；在面板里取消不报错；“打开下载页”可用；更新渠道切换与 Android 表现一致

## 生命周期与异常

- [ ] 卸载后重新安装：需要重新输入邮箱接入并设置 App PIN，旧的 PIN 和面容 ID 解锁不残留；旧设备记录可以在其他设备上移除
- [ ] 签名过期（免费 Apple ID 为 7 天）后重新签名，App 能打开，数据保留
- [ ] 新增或删除面容、指纹，或关闭手机锁屏密码后打开 App：改用 PIN 解锁，提示面容 ID（触控 ID）解锁已关闭，可以在设置中重新开启，数据都在
- [ ] 手机没有设置面容 ID 或触控 ID：设置 PIN 后不询问，设置中不显示这一项
- [ ] 在系统设置中关闭 Harmonia 的面容 ID 权限：改用 PIN 解锁，不卡住
- [ ] App PIN 连续输错 5 次后要求等待，杀掉 App 重开后仍需等待；“忘记 PIN”清除本机数据后可以重新接入
- [ ] 拒绝相机权限：扫码页提示可以改为输入核对码，或到系统设置中允许
- [ ] 被其他管理设备移除后，iPhone 联网即清除本机数据并回到输入邮箱页
- [ ] 签名校验失败或网络不通时，“检查更新”给出明确提示，不显示“已是最新版本”
- [ ] “设置 → 关于 Harmonia”显示版本和开源项目列表，点开任意一项能看到版权说明和许可证全文（Android 同样验收一次）

# v0.3.0：Windows CLI

对应 [rewrite-plan.md](rewrite-plan.md) 第 15 节。以下各项在 Windows 真机上验收；没有列出的命令（环境、变量、本地覆盖、导出）与 macOS、Linux 相同，不重复验收。

**准备：** 一台 Windows 10 或 11 的电脑（普通权限的 PowerShell 窗口即可），一台已接入账号的手机。

## 核心流程

- [ ] **安装**：只看 README，用一行命令装好；全程没有要求管理员权限，也没有要求修改脚本执行策略；新开一个终端后 `harmonia version` 可用
- [ ] **J3 接入**：`harmonia login <服务器地址>`，终端里的二维码能被手机扫到，核对码也能手输；批准后终端显示接入成功，手机的设备列表里这台电脑显示为“Windows”
- [ ] **J4 变量生效**：开启“写入用户环境变量”后，新开的 PowerShell、cmd 和从开始菜单启动的程序都能读到变量；“系统属性 → 环境变量”的用户变量里能看到它们
- [ ] **J4 实时同步**：在手机上修改一个值，几秒后新开的终端里是新值；已经打开的终端不变，`harmonia exec -- <命令>` 在旧终端里也能拿到新值
- [ ] **J4 exec**：`harmonia exec -- cmd /c echo %变量名%` 输出正确；被运行的程序以非零退出码结束时，`harmonia exec` 的退出码相同；Ctrl+C 能结束被运行的程序
- [ ] **后台服务**：安装后立即运行，`harmonia service status` 显示运行中；重启电脑并登录后自动运行，登录时没有窗口弹出或闪过
- [ ] **J10 更新**：发布更高的版本后，`harmonia update` 完成升级并重启后台服务，`harmonia version` 显示新版本；更新渠道切换与其他平台一致
- [ ] **J10 在手机上让电脑更新**：手机上点“更新”后，这台 Windows 电脑在 1 分钟内升级完成，后台服务马上以新版本重新运行（`harmonia service status` 显示运行中），不需要等计划任务的定时检查，也没有窗口弹出；自动更新开关与其他平台一致

## 生命周期与异常

- [ ] **原有变量不丢**：先手动建一个用户变量，再让 Harmonia 写入同名变量，新终端里是 Harmonia 的值；在手机上删掉这个变量（或停用环境）后，新终端里恢复成自己原来的值
- [ ] **系统变量默认不写入**：环境里有名为 `PATH` 或 `TEMP` 的变量时，用户变量里的 `Path`、`TEMP` 保持原样，`harmonia status` 说明它们没有写入以及怎么开启
- [ ] **系统变量开关**：在手机的设备详情页打开这台电脑的“写入系统变量”，几秒后用户变量里的 `TEMP` 变成 Harmonia 的值；关闭后恢复原值。`harmonia shell system-vars on|off` 效果相同，手机上的开关随之变化；Mac、Linux 设备的详情页没有这个开关
- [ ] **撤销**：在手机上移除这台电脑后，后台服务几秒内把写入的用户变量全部恢复，`harmonia status` 显示没有接入账号
- [ ] **到期**：授权到期后，一分钟左右对应的用户变量被恢复
- [ ] **退出登录**：`harmonia logout` 后写入的用户变量全部恢复，开关保持开启；重新接入后自动写回
- [ ] **关闭开关**：`harmonia shell uninstall` 后写入的用户变量全部恢复，之后同步不再写入
- [ ] **卸载**：`harmonia uninstall` 后，用户变量恢复、计划任务消失、数据目录和程序被删除、用户 `Path` 里没有安装目录；重新安装可以正常使用
- [ ] 值里含有 `%`、引号、空格、中文、换行时，新终端里读到的内容与手机上一致
- [ ] 断网时命令给出明确提示；恢复联网后后台服务自动重连并同步
- [ ] 在同一台电脑的 WSL 里安装 Linux 版，两边互不影响（各自是一台设备）

# 电脑作为管理设备

对应 [rewrite-plan.md](rewrite-plan.md) 第 16 节。以下各项在一台 Mac 或 Linux 桌面电脑上验收，Windows 上再走一遍“管理登录”和“批量导入”即可。

**准备：** 一台已有管理设备（手机）的账号；电脑上已安装 `harmonia`，是否已经 `harmonia login` 都可以。

## 管理登录

- [ ] **打开页面**：运行 `harmonia manager`，浏览器自动打开管理页面，终端打印地址并保持运行；地址栏里 `#` 后面的访问码在页面打开后消失
- [ ] **页面内容**：左边说明“密钥留在这台电脑”“由手机批准”“服务器只有密文”，右边是管理登录表单；深色模式和窄窗口下都清楚、没有横向滚动
- [ ] **口令规则**：口令少于 8 位、只有一类字符（如全是小写字母）、或是常见口令（如 `Password1`、`qwerty123`）时，分别提示原因，不发起请求；两次输入不一致时提示
- [ ] **已有日常登录**：这台电脑已经 `harmonia login` 时，表单不询问服务器地址和邮箱，直接显示账号；没有日常登录时两项都要填写
- [ ] **扫码批准**：填好后点“开始管理登录”，页面显示二维码、核对码、设备名和剩余时间；手机“设备 → 添加设备 → 扫码确认”，批准页的“作为管理设备”默认开启，批准后页面几秒内进入管理界面
- [ ] **配对码**：填写手机上生成的配对码发起，手机直接弹出批准页
- [ ] **被批准成普通设备**：手机批准时关掉“作为管理设备”，页面提示重新发起并保持开启；手机的设备列表里没有留下这台电脑的管理身份
- [ ] **取消与离开**：等待批准时点“取消这次登录”、关闭页面或在终端按 Ctrl+C，手机上打开的批准页显示“这次请求已失效”；电脑的数据目录里没有 `manager.json`
- [ ] **手机上的显示**：批准后，手机的设备列表里多出一台名为“<电脑名>（管理）”的管理设备，和这台电脑的日常登录是两条记录
- [ ] `harmonia manager status` 和 `harmonia status` 都显示已管理登录，不询问口令
- [ ] 数据目录里的 `manager.json` 只有本人可读写，其中看不到设备密钥的明文

## 解锁与锁定

- [ ] **再次打开**：结束后重新运行 `harmonia manager`，页面要求输入管理口令；口令不对时提示并可以重输，输对后进入管理界面
- [ ] **自动锁定**：顶栏显示还有多久自动锁定，有操作时重新计时；5 分钟没有操作后页面回到输入口令，并提示“5 分钟没有操作，已锁定”
- [ ] **手动锁定**：点“锁定”立即回到输入口令
- [ ] **刷新与关闭**：刷新页面后仍在管理界面；关闭标签页 30 秒以上，再用同一个地址打开时提示需要重新运行 `harmonia manager`
- [ ] **结束进程**：在终端按 Ctrl+C 后，页面几秒内显示“页面已断开”
- [ ] **地址只能用一次**：把终端打印的地址复制到另一个浏览器打开，提示这个地址已经用过
- [ ] **修改口令**：在“口令与退出”中修改口令，旧口令不对或新口令不合规时提示原因；修改后只有新口令能解锁

## 环境与变量

- [ ] **看到全部环境**：左栏列出账号里的全部环境（包括这台电脑的日常登录没有被授权的），所选环境显示变量数和能读取它的设备数
- [ ] **新建环境**：在电脑上新建环境后，手机上几秒内出现，手机能在里面读写变量；之后在手机上把它授权给另一台电脑，那台电脑能用
- [ ] **改名、删除环境**：改名后手机上同步变化；删除前说明会影响几台设备，确认后手机上该环境消失
- [ ] **变量表格**：值默认遮住，只显示长度；点“显示”看到值，点“复制”能粘贴出正确的值，点“隐藏”恢复
- [ ] **添加与编辑**：添加一个变量、修改它的值，手机上都能看到；名称不合法时提示原因
- [ ] **批量导入**：粘贴一段 `.env` 内容（含注释、带引号的值、跨行的值、一行不合法的内容），对比页列出新增、修改、不变的变量和没有识别的行；“不变”的默认不勾选；导入后手机上的值与粘贴的一致
- [ ] **拖入文件**：把一个 `.env` 文件拖进页面，直接进入导入对话框并已填好内容
- [ ] **多选删除**：勾选几个变量，“删除所选”列出名称，确认后这些变量从手机和各台电脑上消失
- [ ] **跨环境复制**：勾选变量，“复制到其他环境”选择目标后列出新增和修改项，确认后目标环境里的值正确
- [ ] **筛选**：在筛选框输入名称的一部分，表格只显示匹配的变量，全选只选中显示出来的
- [ ] **实时同步**：管理界面开着时，在手机上新增或修改变量，页面几秒内更新

## 退出与异常

- [ ] **在页面里退出**：“口令与退出”中输入口令后退出管理登录，页面回到管理登录表单；手机的设备列表里这台电脑的管理身份消失；`harmonia status` 中日常登录不受影响
- [ ] **在终端退出**：`harmonia manager logout` 询问口令，输对后效果同上；询问口令时直接回车，只删除本机的管理密钥，并提示到手机上移除哪台设备
- [ ] **日常登录互不影响**：`harmonia logout` 之后管理登录还在；只有管理登录、没有日常登录的电脑也能使用管理页面
- [ ] **在手机上移除**：管理界面开着时，在手机上移除这台电脑的管理身份，页面几秒内回到管理登录表单并说明原因；`manager.json` 已删除
- [ ] **唯一的管理设备**：账号里只剩这台电脑是管理设备时，退出前会再确认一次并提醒只能用恢复码找回
- [ ] **断网**：断网时解锁、导入等操作给出明确提示；恢复联网后可以继续
- [ ] **换账号**：这台电脑已经管理登录了账号 A，再用 `harmonia login` 登录另一个账号时被拒绝，并提示先 `harmonia manager logout`
- [ ] **卸载**：`harmonia uninstall` 询问管理口令以通知服务器；卸载后数据目录不存在
- [ ] **给 AI 助手的说明**：`harmonia skill` 的输出写明不要运行 `harmonia manager` 下的命令
